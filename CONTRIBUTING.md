# Contributing to Doki

Start with [workflow](docs/workflow.md), [agent rules](AGENTS.md), [backlog](docs/backlog.md), [engineering proposal](docs/engineering.md) and [design proposal](docs/design.md).

No application implementation is included yet. Accept the bootstrap setup, select a ready feasibility story and resolve platform/stack uncertainties before scaffolding the application. Development commands, pinned toolchains and CI belong to G02 after F03. Do not invent commands or claim builds pass before an implementation exists.

Use one branch and PR per selected story. PRs reference issues without automatic closure. Include acceptance evidence, meaningful check results, documentation and runnable review instructions. The owner accepts and completes each story. The engineering gate remains occupied until acceptance and merge.

Documentation covers all public APIs, schemas, configuration, errors, state transitions, platform limits and user workflows. Use synthetic or licensed fixtures. Keep ROMs, real saves and secrets out of source control. A project license has not been selected; do not imply third-party permission or copy reference assets.
